# Admin-Desktop Control Contract

**Status:** Complete. All 5 surfaces + shell audited. See _Audit coverage_ and _New
findings (no existing slice)_ below.

**What this is:** A verified provenance/truth matrix for every visible control and
metric in `apps/admin-desktop`. For each element it records the promise it makes to
the operator, the **verified** data source behind it, the real action/callable it
invokes, its success and failure/retry behavior, the test that proves it, and a
truth **status**.

**What this is NOT:** A backlog. The fix backlog already exists as
[`docs/agent-tasks/3c-00-admin-ux-completeness-index.md`](agent-tasks/3c-00-admin-ux-completeness-index.md)
and its `3c-*` slices. This contract _classifies what ships today_ and links to the
slice that fixes anything broken. It does not re-spec fixes. When the two disagree,
3c-00 is canonical for _what to build_; this doc is canonical for _what is currently
true_.

**Why it exists:** A command center is judged by truth, not by how serious the UI
looks. A beautiful control that lies is worse than a plain one that admits "unknown."
This contract makes every claim the admin app makes auditable against code.

## Method (binding)

Every `Status` in this document was assigned by **reading the code path**, not from
memory. Each row cites a `file:line` for its source and action so any reviewer can
re-verify. A claim that could not be traced to code is marked **Unverified**, never
**Real**. Re-verify line numbers before acting on a row — they drift.

## Status taxonomy

| Status          | Meaning                                                                                                                                              |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Real**        | Backed by a verified data source; if it is an action, a verified callable. Has both a success and a failure state.                                   |
| **Partial**     | Real source/action, but a state is missing or misleading (failure only logged, no retry, or a default that reads as a real value before data loads). |
| **Unverified**  | Source/action exists in code but runtime resolution to real data was not confirmed here (needs emulator/runtime proof).                              |
| **Fake / Dead** | No real source/action behind it, a metric derived from never-populated data (actively misleading), or a control with no call site.                   |

Column mapping to the requested schema: _UI element_ = Control · _User promise_ =
Promise · _Real data source_ = Source · _Real action/callable_ = Action · _Success
state_ + _Error/retry state_ = States · _Test proof_ = Proof · _Status_ = Status.

### Dashboard findings (carry into the backlog, do not fix here)

1. **One fabricated metric:** the StatusBar "uncovered" count is the only actively
   _lying_ element on the surface. Fix is already scoped as
   [3c-16](agent-tasks/3c-16-dashboard-coverage-truthgate.md) (derive from the
   `useResponderFleet` data already in scope, or remove the metric). **Highest
   priority** — it is the clearest instance of false authority.
2. **Two load-time false-alarms / swallowed failures:** FCM rate renders `0%` before
   the first poll (`?? 0`), and `getOpsMetrics` poll errors never reach the bar. The
   Declare-alert page handler only `console.error`s. None are scoped yet — **new
   findings.**
3. **Honest-unknown is already a proven pattern here.** `MunicipalPerformanceTable`
   is the reference implementation: missing data → "No telemetry," not a fake zero.
   The fix for finding 1 is to make the StatusBar behave like this table.
